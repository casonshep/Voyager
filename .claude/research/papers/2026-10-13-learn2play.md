# Learn2Play Bench

## What it is

Twenty newly designed text games with hidden, sometimes counter-intuitive rules, played for 5
episodes (10 for the five challenge games) with deterministic feedback and automatic scoring.
Half the games re-shuffle characters, objects or layouts across episodes while keeping the rule.
This separates "learned from interaction" from "already knew from pretraining".

## What it says

- **Metrics**: Max, Mean, Learning Gain (last k minus first k episodes), Learning Slope (linear
  fit); challenge games weighted 3x.
- **Backbones** (Table 1, OpenCode harness): Opus 5.5 best Max/Mean (80.1 / 61.0); Qwen 3.8 Max
  best LG/LS; GPT-5 Mini worst (34.0 / 22.3). Stronger models revise their rule hypotheses when
  observations contradict them; weaker ones repeat actions that worked before.
- **Methods** (backbone fixed): MEMORY (complete, unmodified histories of earlier episodes added
  to the prompt, oldest dropped at the context budget) leads Mean, LG and LS with Kimi K3 and
  beats Reflexion, ReasoningBank, AWM and EvoTest on average (Reflexion keeps a slightly higher
  Max). "Reflection and memory processing can turn an incomplete understanding into rules or
  workflows that later episodes continue to follow, while raw histories keep the original evidence
  available for revising those interpretations." Case B.1.3: after one failed gem fusion, an
  EvoTest prompt told the agent "never to attempt tier-2 or tier-3 fusion, ruling out combinations
  it has not tested."
- **Harness** (Sec 4.3, 4.6): Claude Code and Codex beat OpenCode with the same backbone;
  OpenCode beats every scripted self-evolving method and costs less because it "executes several
  actions from one model response and removes repeated game feedback" (8.1 model calls per
  episode vs 24 to 30; 56% fewer input tokens than MEMORY). Costs per episode: Claude Code +
  Opus 5 $0.65 (Max 81.8); OpenCode + GPT-6 Astra $0.25 (76.2); MEMORY + Opus 5 $3.09 (60.9);
  EvoTest's between-episode updates alone cost 11.5K tokens per episode.
- **Humans vs agents** (Sec 4.4): human Top-1 Max 84.3 beats every agent. Consecutive-episode
  action-sequence similarity (difflib SequenceMatcher) 0.54 for humans, 0.66 for agents; after a
  worse episode humans set a new best 33% of the time, agents 22%. Agents win when success needs
  long exact sequences or calculation (RedEye, Model Auditor).
- **Transfer** (Sec 4.5): re-shuffled instances slow learning, more for weaker backbones; agents
  that remember what worked but not why repeat a menu position after the menu changes.
- **Rules without planning** (Sec 4.2.3): Haunted Inn, the agent knows the taboos and still
  assigns rooms greedily.

## What the code contains

Games only: `play.py <game> --seed S --episode N`, actions on stdin, a `--replay-json` endpoint
returning `{observation, valid_actions, score, done}`. No prompts, no MEMORY format, no harness
wiring. TeX source on arXiv has the appendices (cost tables, cases).

## What applies to this project

- **Keep raw histories; make distilled rules revisable from them.** Maps to: library, builder
  prompt. Addresses: F5, F1. Proposal: persist per-decision records (R2); any lesson or remedy
  cites record ids; raw traces stay authoritative when a lesson is challenged (R4).
- **Measure and counter over-exploitation.** Maps to: Jev loop sampling temperature
  (`agentLoop.js:31-32`). Addresses: F1 (same design rewritten seven times). Proposal: compute
  attempt-to-attempt action-sequence similarity per subtask as a metric (R8) and as a state
  feature Jev can see.
- **Fewer, larger model calls with batched actions.** Maps to: builder. Addresses: F3 (rigid
  three-draft loop). Proposal: let the builder run and observe several bounded actions in the
  fake world before registering a trial (R7); trim repeated feedback.
- **Harness choice matters more than the self-evolving method.** Maps to: the whole Python
  orchestration. Note for later: a coding-agent-style builder session (model decides when to look
  at traces) may beat our prompt-and-parse, at lower cost.
- **"Remember why, not just what."** Maps to: library sidecars. Proposal: store the trigger
  context and precondition with each proven primitive, not only counts (MineEvolve schema in the
  survey file).

## What does not apply

Text-only games with enumerated valid actions; no embodiment, no real-time constraint.

## Open questions

- MEMORY's win is with Kimi K3; with Opus 5 the methods are close. Which regime is gpt-4o-mini in?
- Their cost numbers assume one model call per game action; our Jev calls are not comparable.
